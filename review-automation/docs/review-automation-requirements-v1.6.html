一句話目標

最高目標(北極星——即所有取捨的最終裁決標準):入職 Etched 後,常態週工時中位數 ≤ 8 小時/天。本系統是手段,兩條作用路徑: 壓低平均(理解成本 → attention allocation)、壓低 tail(incident、迷航日 → U2 / B 線), 外加副產品 output legibility(evidence-backed 產出 = 不被盯工時的資本)。
把「理解成堆 issue 與 AI 產碼」的成本壓到最低。系統真正的產品是 attention allocation——告訴你該把眼睛放在哪、依什麼順序; summary 只是副產品。所有產出以證據(file:line span)為單位,可點開驗證。

使用情境與約束

  • 單人使用,本地優先:Fedora + systemd --user + tmux。CI 為第二階段鏡像,同一條 pipeline。
  • Tracker-agnostic:2026-10 換公司,forge / issue tracker 必換。 所有 tracker 接觸點走 adapter 介面(normalized issue schema),換來源只換 adapter。
  • 語言環境:繁體中文(台灣用語)為 human-facing 預設,技術術語保留英文; style guard 為一級公民而非事後補丁。

非目標(紅線)

  • 永不 auto-approve / auto-merge based on LLM verdict。自動化的是理解,判斷留在人手上。
  • 不維護「活的」架構圖。所有視圖 per-review 生成、ephemeral、可丟棄。
  • 不做全 repo 毛球圖。一切 graph 以 diff 為錨,展開一跳為上限(預設)。
  • 不把 Heptabase 當資料庫。機器狀態活在自動重生的 board;Heptabase 只收人工 promote 的東西。
  • 不在 hook 內跑 LLM 或任何秒級以上工作。hook 只 enqueue。

共用核心(C)

所有 workflow 共用的引擎與紀律。違反任何一條視為架構回歸,不是風格問題。
ID需求備註 / rationale期
C1 Claims-with-spans:所有 LLM 產出為結構化 JSON;每個 human-facing claim 必附 file:line span 或 evidence 連結。無 span 的 claim 不得進 renderer。 LLM 負責「指」。這是整個系統可信度的地基。 v0
C2 Validator:span 存在於該 commit;claim 提及的 symbol 實際出現在 span 內。不合格 → retry 一次;再敗 → 丟棄該 claim 並計入 degraded 統計。 便宜、deterministic,擋掉幻覺定位。 v0
C3 LLM 指不抄:renderer 一律從真實 checkout 取 code 內容顯示;LLM 輸出永不包含要顯示的 code 本文。 它頂多標錯,你看到的 code 永遠是 ground truth。 v0
C4 Deterministic skeleton:graph 的節點與邊(symbol、call、import)由 tree-sitter / git plumbing 產;LLM 僅做語意標註,不得新增邊。 LLM 畫的假邊比沒圖更糟。 v0
C5 兩層 cache:deterministic 層 key = commit hash;LLM 層 key = (diff hash, input set hash, prompt version)。cache hit 不重打 API。 讓重跑近乎免費,才敢自動化。prompt 版本見 I5。 v0
C6 Model tiering:抽取 / 分類 / lint 級任務用 Haiku 級模型;requirement mapping、假說生成才上大模型。 成本結構決定這系統能不能一直開著。 v0
C7 Budget guard:worker 記帳,單位隨 backend——API 模式 = token / 金額;subscription 模式 = 請求數 / rate-limit window(I7)。超額自動降級為 Tier 0 only 並通知。 沒有 guard 的自動化 LLM pipeline 會在你不注意的那週燒錢(或燒光你的互動 quota)。 v1
C8 失敗顯性化:任一 stage 失敗、或 validator 拒絕率超閾值 → 產物頂部 degraded banner + notify。禁止渲染「看起來完整」的半空產物。 Silent failure 是自動化系統最毒的病。寧可整份標紅。 v0
C9 Style guard 前置:所有 human-facing prose 在 renderer 前必經 S 線(v0 至少 lint;editor 依期別)。結構欄位(span、ID、path)不經過。 защ辯護這類東西永遠到不了你眼前。 v0
C10 寫回分級:機械送達(CI 貼自家 artifact 連結)直接開;LLM 判斷型寫回(label、dedupe 連結、追問留言)read-only 試用 ≥ 2 週且 precision 驗過才開;auto-approve / auto-merge 永不。 政策,即日生效。 政策
C11 Untrusted input 紀律:issue / PR 描述等外部文字一律視為資料;不得驅動任何寫入動作。任何會「執行」外部輸入的環節只能在 sandbox(I4)。 否則你親手蓋了一條 prompt injection 進開發機的路。內部 tracker 也照做,紀律成本為零。 政策
C12 Hit-rate 迴路:凡預測型 claim(假說、分類、risk rank)須可回填對錯;issue 關閉 / PR merge 時記帳,儀表可看趨勢。 沒有 hit-rate 的假說系統不可證偽——你不知道它在幫你還是害你。 v2
C13 Findings → rules 飛輪:review 中重複出現的 finding,一鍵固化成規則——去向三選:CLAUDE.md(模型該知道)、lint / hook(不可違反)、A4 risk 表(加權排序)。S8 是本條的 style 特例。 Google 飛輪的單人版:嚴格 + 快的 review 教會作者,下次送來的就是好的。 v1
C14 解鎖判準:v1+ 的每一條,解鎖時須同時答出「對應哪個實際痛點」與「每天替常態工時省幾分鐘 / 砍哪個 tail」;答不出不建。建成後四週未被使用 → 刪除,不留念。 北極星的執法條。系統不得變成吃掉 8 小時的嗜好。 政策
C15 Build window:v0 與 v1 核心於 2026-10-05 前完成;入職後 90 天內對本系統只當使用者(修 bug 可,不開新線、不加需求)。 Ramp 期邊上班邊造工具是最典型的 8 小時殺手。寫成政策,擋住我們兩個。 政策

Review 線(A:PR dossier · L:session ledger)

回答「這包 diff 到底在幹嘛、跟它聲稱要解的問題對不對得上、我該先看哪」。上游先整形,下游才分析。

G — 上游整形(generation-side)

最大的 lever 在這:與其造精緻的機器消化不可審查的 blob,先要求 blob 不出生。實證:超過 200–400 行,人找缺陷的能力開始崩。
ID需求備註 / rationale期
G1 Reviewable series:Claude Code 產出以邏輯變更為單位的 commit 序列——每 commit 一件事、可 bisect、message 含 intent(why)。預估變更超過 budget 的任務,必須先提切分計畫再動工。CLAUDE.md 合約 + hook 驗證(commit 粒度 / message 格式)。 Kernel patch series 紀律的 agent 版。A3 的 scope-creep 偵測是下游保險,這條是上游預防。 v0
G2 產出預算:planning / design doc 有行數 budget 且答案先行(決策記錄格式:context → decision → consequences,細節進 opt-in appendix);code 每邏輯 commit 有行數 budget。超 budget → 先切分。CLAUDE.md 合約 + doc-length lint hook 作 floor。 沒人讀完的文件是負資產:燒 token 又製造「有文件」的假象。budget 數字由你定(Q 待補)。 v0
G3 Agent-legible = reviewer-legible 的 code 合約:boring 優先——平鋪、描述性命名的函式勝過聰明抽象;可 grep、局部推理;意圖寫進 doc comment(agent 可反查註解與實作不一致)。 Ronacher:agent 依賴局部推理與 grep;對 agent 好讀的 code 對過載的 reviewer 也好讀,同一條紅利收兩次。 v0
G4 Delegation routing:你熟到能預測其行為(U4 can-predict 以上)且 blast radius 大的區 → 手寫或緊迭代(互動 session、小 diff、逐步 review);熟但外圍 → 皆可,agent 雜活你秒審;規格良好的轉換 / 鷹架 / 不熟的外圍 → 交 agent;不熟但 load-bearing → agent 可起草,必配 U2 補 theory,否則就是在核心區養 dark 地帶(U4 紅線)。體感速度不可信,以 I6 量測校準路由。 METR:熟悉的成熟 repo 上,體感 +20% 實測 −19%。Gjengset 的「delegation 直覺」顯性化成政策。 政策
G5 Next-action 合約:每輪對話、每份產物的結尾必附「需要你的只有…」區塊,≤ 3 項,且只列真決策;下一步無歧義時寫「nothing——接著做 X,喊停即停」。不得製造假決策換確認。該讀者做的事被埋在產物深處 = 生成端失職。 本文件頂部的待拍板條就是實作。也進 CLAUDE.md,對 Claude Code 同樣生效。 政策

A — PR / diff 導讀 dossier

ID需求備註 / rationale期
A1 輸入 = branch diff(base 自動偵測)+ 關聯 issue。issue 來源優先序:session ledger → branch 命名約定(Q2)→ 手動參數;缺 issue 時降級為純 diff dossier 並標示。 降級要顯性,免得以為 matrix 是空的。 v0
A2 Diff → symbol mapping:每個 hunk 對應 enclosing symbol(tree-sitter),並展開一跳 caller/callee 形成 scoped subgraph。 Diff-anchored,永不全 repo。 v0
A3 Requirement ↔ span 雙向矩陣:issue 拆 requirements,每條對到實作 spans。雙向 gap 顯性標記——未實作需求;以及 unmapped hunk(scope-creep 嫌疑),排序最前。 這是「圍繞要解的問題看 code」的核心機制;AI 產碼最需要盯的就是 drive-by。 v0
A4 Risk ranking:unsafe、lock/atomic、error path(let _ =、非測試 unwrap)、API surface、serialization / config 變更加權排序 hunks。規則表資料化,可隨時加條目。 稀缺資源是注意力;這就是排注意力的地方。 v0
A5 Test-weakening detector:同一 PR 內 assertion 刪除 / 放寬,與其對應被測碼變更共現 → 高亮。 Agent 為了讓測試過而改測試,是已知模式,值得專門抓。 v1
A6 Data flow 視圖:沿 call path 抽 function signatures / types 作 edge 標註(Rust 先行)。 Rust 的 signature types 本身就是大半的 data flow 文件,免真 def-use 分析。 v1
A7 輸出:單檔 HTML dossier(subgraph pane + code pane + matrix + ranked hunk list),Gruvbox Material dark,離線可開、可留檔。 Ephemeral 視圖,不維護。 v0
A8 觸發:SessionEnd job 與 pre-push 走本地 worker(v0);PR update 走 CI 跑同一條 pipeline(v1)。 同 pipeline 兩個殼,不分岔實作。 v0
A9 Review budget 顯示:dossier 標示本次審查負荷(v0 = 素樸 LOC;v1 = A4 風險加權有效行數),超過 400 行等級即警告並附切分建議。 系統過載有 C8 banner;人過載是靜默退化成語法檢查——要在到達你之前擋。 v0
A10 註解 ↔ 實作一致性:dossier 對變更區的 doc comment 與實際行為做一致性標註,不一致即 signal。 Hashimoto 的實踐反向工程:密集註解讓 agent 能抓 comment-code 矛盾——便宜的語意 diff。 v1
A11 Block-ask 迴路:dossier 的每個 claim / span 附「問這段」動作——帶著 span 走 K 通道開問,答案成卡並回鏈 dossier 原位。 「點開拿去問、再放回來」的最小可行版;Pi 的 tree-branch session 證明這個互動需求真實存在。 v1

L — Session ledger(Claude Code 側)

ID需求備註 / rationale期
L1 SessionEnd hook 只寫 job spec 進 queue 即退出(< 1s):不跑 LLM、不 block、不做網路呼叫。 Hook 有 timeout;fire-and-forget 是鐵律。 v0

L3 聲稱 vs diff 對帳:ledger 聲稱與實際 diff 的落差,列入 dossier 的 signal 區。 落差本身就是 review 訊號。 v1
L4 Stop hook 不用於觸發 pipeline(它每個 turn 都 fire);Stop 只保留給 style lint(S6)。 政策。踩過的坑寫成規則。 政策

Issue 線(B:event-driven brief)

Issue 進來幾分鐘內,一份預消化 brief 落地。分類標籤價值低,證據鏈才是產品。
ID需求備註 / rationale期
B1 觸發與來源:tracker adapter 介面(list / get / normalized issue schema);webhook 有則用,無則 timer 增量 polling。換 tracker 只換 adapter(見 Q1)。 十月換環境,這條是保命符。第一個 impl = Jira(Q1 已決);forge 側 = GitHub。 v1
B2 Tier 0(每 issue 無條件、秒級、零 LLM):anchors 抽取(error string、stack、path、symbol、版本)→ grep 定位;git log -S + blame 嫌疑區;近期 commit / PR 關聯;相似舊 issue 候選。 「這區三天前剛被改過」常常就是答案的八成。雛形已存在(experiments/triage.py,真 repo 驗證過),即日手動可用;v1 由 worker 收編。 v1
B3 Tier 1(分鐘級):分類 + confidence;bug → 因果假說鏈(條件 → 路徑 → span),必附 ≥ 1 個 alternative;feature → requirement 拆解 + blast radius;缺料清單(缺 repro / 版本 / log)。 自信的錯誤假說比沒有假說更毒——alternative 與 confidence 是強制欄位。 v1
B4 Dedupe:先粗聚類(anchors / embedding),LLM 僅在 cluster 內 verify;結果附連結供人工確認,永不自動合併。 避免 O(n²) pairwise;false positive 由人擋。 v1
B5 Tier 2(gated):sandbox worktree 內嘗試重現——寫 failing test 或跑 scenario。Gate = 有 repro steps ∨ crash / security 類 ∨ 手動 promote。結果 async 併回 brief(「brief updated: repro 成功 / 失敗」)。 全量自動開 = 成本爆 + 攻擊面。sandbox 規格見 I4。 v2
B6 Brief 落入 triage board;board 每次增量後整頁重生(disposable、永遠最新)。 機器狀態的家在這裡,別處都是投影。 v1
B7 假說 hit-rate:issue 關閉時回填(對 / 錯 / 未驗),接 C12 儀表。 幾週後你才知道 Tier 1 值不值得信。 v2
B8 追問草稿:缺料時自動草擬回覆給 reporter;實際發送屬 LLM 判斷型寫回,受 C10 管。 草稿免費,發送要過試用期。 v2

T — 自主解題線(龍蝦線:issue → 環境 → 重現 → 修補嘗試)

順序是安全帶:review 線(A)是 T 線的前置。沒有 dossier 消化力就開自主修補 = PR 洪水——高 AI 採用團隊 PR +98%、review 時間 +91% 的資料就是這個病。
ID需求備註 / rationale期
T1 環境推斷:從 issue + repo 訊號(Dockerfile、flake.nix、Cargo.toml、CI 設定)推斷 runtime,產 sandbox 配方(nix devshell 或 container,Q4);人可覆寫配方。 B5 sandbox 的供給側。推斷失敗 → 顯性標示、退回手動,不硬猜。 v2
T2 Deploy-test-retry harness:sandbox 內自主迴圈(重現 → 修補嘗試 → 測試 → retry),硬預算(次數 / 時間 / token);產出 = 重現證據 + failing→passing diff + 自述 brief;寫回僅止於 patch 提案(C10:永不自 merge);起步一律手動 promote,自主度隨 C12 hit-rate 升級。 迴圈本體 Claude Code / agent 就是;我們加的是 harness:供給、預算、證據、閘門。 後
T3 Diagnostic playbooks:按 problem-class 的分析配方庫(skill 檔形式,依 B3 分類載入)。三個來源:已解 issue 的 postmortem 蒸餾(C13 延伸到診斷)、U2 failure maps、K5 熱區;候選經人審才入庫。 「解過的問題的分析方向」變成可載入資產——整個系統的知識複利點。Playbook 是持久化的指令注入面:入庫需人審 + 版本 + 簽名。ZeroClaw 的 skill 檔模式是現成前例。 v2

Style guard(S)

三個躁源分開治:script 漏字(защ)→ lint 攔;翻譯腔 calque → editor 改;register 陸詞 → 詞典 + OpenCC。
ID需求備註 / rationale期
S1 style.toml 單一資料源:術語 allowlist、banned map(爛詞 → 替換)、script whitelist(Han / Latin / 常用標點)、語氣規則。CLAUDE.md 引用它(模型「知道」),lint / editor 消費它(系統「強制」)。 判準:模型忽略一次的代價可忍 → CLAUDE.md;不可忍 → lint。 v0
S2 Lint(deterministic、零 LLM):Unicode script 掃描(白名單外 script 直接 fail)、OpenCC s2twp 轉換後 diff(抓簡體與陸詞)、banned map 比對。 100% 攔截 защ 類、零誤放、零成本。 v0
S3 Editor(LLM rewrite):獨立 call、乾淨 context——只給文字 + style spec,不給任務脈絡;Haiku 級模型。 叫產出者「順便自審」沒用:偏差的 context 還在,它覺得自己寫得挺好。解鎖制:S2 lint 上線後仍被 calque 惹到 ≥ 每週一次才建。 後
S4 Masking:rewrite 前將 code span / identifier / 數字 / 路徑 mask 成 placeholder,改後還原並驗證 anchors 原樣存活;術語 allowlist 保護 + 「不確定就保留原文」規則。 物理上碰不到技術內容;壓住語意漂移與「順手修掉術語」兩個風險。隨 S3 解鎖。 後
S5 Pipeline 接點:renderer 前一站,只過 JSON 中 human-facing prose 欄位。lint fail 可機械修者(OpenCC)就地修;不可修者把違規清單 append 回 LLM retry。 Claims 結構在這裡又賺一次:結構欄位完全不動。 v0
S6 互動 session 接點:Claude Code Stop hook 跑 lint(便宜,每 turn 可跑);exit 2 把違規清單餵回模型,session 內自我修正到過為止。 你看到的已經是修過的版本。 v1
S7 反身規則:linter 乾淨即沉默;可自動修就不問;永不 nag。 政策——style guard 自己不准變成新的躁源。 政策
S8 回饋迴路:一個指令把「惹怒句 + 你的改寫」加入 banned map 與 editor few-shot。 躁的瞬間直接變規則;真實惹怒你的樣本比任何泛用風格指南都準。 v1

Infra(I)· 送達(D)· Heptabase(H)

執行基底、結果送達、以及與思考空間的邊界。

I — 執行基底

ID需求備註 / rationale期
I1 Job spec JSON schema + queue dir 慣例:檔名含 type / branch / timestamp;寫入走 tmp + rename(原子)。 Queue 是介面,hook 與 CI 都只認它。 v0
I2 Worker 啟動層走薄 adapter:Linux = systemd --user path unit;macOS = launchd WatchPaths。worker 自身不監看檔案,被喚起後 --drain——啟動機制歸 OS,binary 保持可攜。失敗與歷史 journalctl / log show 可查。 兩平台皆用原生機制,不引入額外 daemon 框架。 v0
I3 Debounce:同 branch 的 pending jobs 合併,只跑最新 HEAD。 連續 commit / 連續 session 不重複燒。 v0
I4 Sandbox 規格(所有會執行外部輸入之處):隔離階梯依風險爬——Tier 1(不執行)worktree 即可;Tier 2 起跳 rootless container;T 線自主 = microVM / gVisor 級,且優先跑在犧牲主機(無 SSH key、無公司 code)。bare worktree + systemd sandboxing 明確定位為衛生而非安全邊界。皆為 throwaway、無 credentials、網路 deny-by-default、產出僅 claims + report。 C11 的實作面。 v2
I5 Prompt / schema 版本化:任何 prompt 或輸出 schema 變更 → bump 版本 → LLM cache key 失效(接 C5)。 否則改了 prompt 還在吃舊 cache,除錯地獄。 v0
I6 可觀測:每 job 一行結構化 log——耗時、token、cache hit、degraded 與否。 C7 budget guard 與 C12 儀表的資料來源。 v1
I7 LLM backend 抽象:統一契約 (prompt-id, inputs, schema) → validated JSON;兩個 impl——claude-code(headless claude -p,吃訂閱)與 api(直打 API,key 走 env / systemd credential)。v0 定 trait、出一個 impl(Q6);第二個 impl v1。 Validator(C2)在 backend 之上,品質要求不隨 backend 變;也讓這套東西可分發給沒有 API key 的人。第三 impl 候選:Pi(print / RPC mode)——model-agnostic 逃生口,同席位可換 Codex 或其他模型。 v0
I8 Per-task routing:任務類宣告需求(clean-context / schema-strict / agentic / model tier),router 映射到 backend。S3 editor → 需 clean-context(API 天然;claude -p 需在空目錄跑避開專案 context);Tier 2 → 需 agentic(Claude Code 天然);CI(A8)→ 實務上只有 API key 路。 差異是能力面,單一 backend 硬吃全部任務會在某處妥協。 v1
I9 Subscription 模式禮讓:pipeline 不得餓死互動使用——併發 = 1、per rate-limit window 的 job 上限、一鍵暫停自動化;可設定僅離峰跑。 自動化跟你的互動 session 搶同一個 quota;SessionEnd 觸發的 dossier 不該害你下一個 session 撞牆。 v0
I10 Credential broker:model API 與 forge / tracker token 永不進 sandbox;沙盒經 broker socket 請求能力,broker 代理呼叫並施加 per-job 短命、限額、全程審計;secrets 以 systemd LoadCredential 管理,不落 env / 檔案。 Claude Code 跑在沙盒內 = token 在沙盒內,隔離再好也是鑰匙鎖進賊的房間——所以呼叫權留在外面。 v2
I11 Egress 於 guest 之外強制:per-job netns 或宿主 nftables,deny-by-default + allowlist proxy;依賴預先 vendor,build 走 --locked --offline。 多數攻擊的目的是外洩,殺出口 = 殺動機;執法點在 guest 外,kernel 逃逸才帶不走它。供應鏈順手一併收。 v2
I12 Tainted output(C11 的對稱面):沙盒產出一律視為污染——僅結構化資料過 schema + validator(C1/C2 氣閘)得進下游;log 文字消毒 ANSI / OSC escape;T2 patch 提案必經 dossier pipeline 同級審查。 惡意 issue 的真正落點常是「回來的東西」:帶後門的合理 patch、注入下一個 stage 的文字。scope-creep 偵測在此即後門偵測。 v2
I13 Assume breach:per-job exec 與 egress 審計(宿主側),異常即殺 + job 隔離 + C8 通知;沙盒內佈 canary credentials 作絆線;job 間零持久。守恆律:自主度 × 特權 ≈ 常數——hit-rate 掙自主,永不掙 credentials。 打不穿是妄想;打穿必被看見、且無利可圖,是工程。 v2
I14 macOS 全功能:v1 核心(worker、lint、triage、NOW、matrix)在 Apple Silicon macOS 原生可跑——launchd adapter、通知 adapter、Rust 目標 aarch64-apple-darwin、不用 Linux-only syscalls。 2026-10-05 起主工作站是 Mac(M4);Fedora 降為個人機與 sandbox 執行層候選。公司 code 不落個人硬體(Q8 邊界)。 v1
I15 Hub-and-spoke 拓撲:基礎設施(worker、queue、renderer、serving、timers)以「hub 角色」部署,依 repo context 選機——個人 = Fedora 工作站常駐;工作 = 公司硬體(Mac 自 hub,或公司 devbox,見 Q8)。Mac 為漫遊 client。 Hub 是角色不是機器。常駐 hub = 闔蓋不斷線、timer 有家、board 成為任何裝置可達的 URL。 v1
I16 跨機 enqueue(解鎖制):hook 永遠只寫本地 spool(L1 不變);syncer 非同步把 job + git bundle(攜未 push commits)推上 hub;hub 以 mirror clone 重建 context。 Colocation(session 開在 hub 上)吃掉多數需求;僅「離網在 Mac 寫個人專案」真的痛才建(C14)。 後

Progress(P)· 理解(U)

「太長」的三種病分開治:文件太長 → rolling state;歷史太長 → append-only log + 檢索;時程太長 → evidence-backed matrix。理解沿 failure 軸建,不沿 code 結構軸。

P — 進度追蹤

ID需求備註 / rationale期
P1 Rolling state file(NOW.md):Now / Next / blocked-on + worktree 現況表(branch @ commit、ahead/behind origin,機器自動產)。硬 budget 40–60 行,覆寫式更新,永不累積。 Cumulative doc 是「太長」病原體。自動產的 state 天生不 stale(stale-ref 事故直接被預防)。Ronacher 的實踐也落在「session 之間寫 markdown state」這個形。 v0
P2 Append-only decisions / incidents log:決策與事故教訓(如 stale-ref)只進這裡;永不線性重讀,靠 grep / anchors 檢索。 Incident 的生命週期是永久,state 的生命週期是當下——分家。 v0
P3 Acceptance matrix as progress:每條 requirement 的狀態機(todo / authored-not-run / passing / delivered / out-of-scope)必須 evidence-backed——spans + 測試輸出 / log 連結;agent 自報完成不改變狀態。deploy-test 結果回填矩陣。 A3 拉到專案層級。手動版即日可用(§10b 矩陣就是骨架)。 v1
P4 SessionStart hook 自動餵 NOW.md 進 context;SessionEnd 從 ledger(L2)推導 state 更新,以候選 diff 形式供你確認。 重建脈絡的成本歸零;更新不靠你記得。 v1
P5 30 秒 view:渲染後的 acceptance matrix + NOW.md 合成單頁,一眼讀完(骨架校準中,Q7)。 打開一個東西就知道現況——超過 30 秒就是失敗。 v1
P6 Pending-on-you queue:所有等你決定的事集中唯一位置——NOW.md 的 blocked-on(you) 區 + 文件頂部待拍板條;chat 與其他產物只指向它,不散落。 「找不到在哪裡」的根治:固定位置 + 單一來源。 v0

U — 理解 / ownership

Verification 證明系統 works;incident 需要系統被 owned。AI 產碼的特有病:theory 從未在任何人腦裡存在過。目標是校準過的理解——核心深、外圍有圖、淺處誠實並配義肢(B2 anchors / dossier)。
ID需求備註 / rationale期
U1 Done 定義分層:load-bearing 組件 = 證據(P3)+ 通過你的預測考核;短生命週期產物可降標,審查深度隨 lifetime 與 blast radius 調。 Hashimoto 的分層:長命專案逐行審,丟棄式專案零審。test 認證系統,考核認證工程師。 政策
U2 Failure map 方向性:由你不看 code 憑記憶寫一頁(組件、invariants、「X 掛掉時系統怎麼反應」),Claude 對 code 逐條驗證標對 / 錯 / 不完整並附 span。寫不出的格子 = theory debt 的測量。 Claims+spans 的對稱應用——這次過 validator 的是你的 claims。你寫他驗,學習價值與他寫你讀相反(Cisco 自註效應倒過來用)。 v0
U3 Fault-injection + fuzz drill:從 failure map 挑最可怕的格子注錯(kill daemon、斷依賴、餵垃圾),先預測後觀察;load-bearing 組件以 agent-driven fuzz / property tests 為預設驗證。drill 暴露的 observability 缺口自動開 issue。 Dan Luu:agent fuzz 找到「叫 AI audit code」找不到的 bug 類。預測與現實的 diff 是最高價值學習時刻。 v1
U4 Acceptance matrix 加 understanding 欄:dark / mapped / can-predict / can-debug。紅線:Tier-1 blast radius 內不准有 dark。 理解狀態顯性化,才管得動。 v1

K — 知識線(session 內問答的彈射與回收)

任務 session 拋棄式,知識永久——生命週期不同就分家(同 P 線病理)。知識問答不深談於任務 session;彈射、批次解答、落回可檢索的家。
ID需求備註 / rationale期
K1 問題分流:task-blocking 問題留在 session、答案 ≤ 10 行(CLAUDE.md 合約);知識型問題不在任務 session 深談,一律彈射進 knowledge queue。 Context 汙染讓模型在正事上變笨,訂閱模式還多燒 quota;深談的正確場所在批次線。 政策
K2 零摩擦捕捉:一行指令(shell / nvim / tmux keybind)把問題落進 queue,可附當下 code span;不打斷 flow。 捕捉成本 > 3 秒就沒人用。手動版今天可用(later())。 v1
K3 批次解答:worker 新增 knowledge job type,離峰逐題產 atomic card(一卡一概念、G2 預算);重複大主題可產 Gruvbox 教學 artifact。 同一條 pipeline 換 job type;I9 禮讓天然適用(離峰跑)。 v1
K4 落點與檢索:knowledge/ 目錄(greppable、mdview、含 provenance:觸發的 session / span);可選推 Heptabase save_to_note_card 進 Inbox。 知識卡是 H 線的本命 use case——那本來就是思考空間該裝的東西。 v1
K5 Theory-debt 訊號:問題按 area 聚類;熱區(同區重複提問)→ 提示對該區做 U2 式 deep-dive。 U2 主動探測理論債,K 線被動量測,兩邊夾。 v2
